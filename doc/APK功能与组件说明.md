# SushiVIP APK —— 功能与组件说明

> 给**网络平台工程师 / 运维 / 后续接手的开发**看的一份说明：
> 这个 APK 到底做了什么、由哪些组件构成、对网络和服务端有什么要求、
> 以后想调整时该动哪里。
>
> 相关文档：[`执行说明.md`](执行说明.md)（部署步骤）、
> [`平台端调整说明.md`](平台端调整说明.md)（Web 侧对接）、
> [`设计与问题记录.md`](设计与问题记录.md)（设计理由与历史问题）

## 一、它是什么，不是什么

| | |
|---|---|
| **是什么** | 一个**只加载单一内网站点**的原生浏览器外壳（WebView 容器） |
| **不是什么** | 不是浏览器、不是业务应用。**没有任何业务逻辑**，所有页面、接口、数据处理都在服务端和前端 |

**关键推论**：业务出问题基本不用怀疑 APK。
容器只负责四件事 —— 把页面装起来、把设备能力递给网页、把错误拦下来、把地址藏起来。

包体全部代码约 1600 行，**零第三方库**，只用 AndroidX 官方组件。

| 项 | 值 |
|---|---|
| 应用名 / 包名 | SushiVIP / `net.sushisom.sushivip` |
| 支持系统 | Android 12 及以上（实测覆盖 Android 12 与 Android 16） |
| 目标地址 | `https://lms.sushisom.net/`（编译期写死） |
| 屏幕 | 强制横屏、全屏沉浸（隐藏状态栏与导航栏） |

## 二、功能清单

### 2.1 显示与交互

| 功能 | 说明 |
|---|---|
| 强制横屏 | 锁定不随重力翻转。**各厂商「自然方向」定义不同，换机型要重新确认充电口朝向** |
| 全屏沉浸 | 隐藏状态栏和导航栏，从边缘上滑可临时呼出 |
| **正常息屏** | 刻意**不**阻止息屏，门店要求省电。会话靠 Cookie 落盘扛住息屏 |
| 加载过渡 | 白底 + 品牌 logo + 进度圈，避免白屏跳变 |
| 返回键 | 网页有历史则后退；已在首页则弹「确认退出」 |
| 缩放 | **已禁用**，页面必须在平板原生分辨率下直接可读 |

### 2.2 递给网页的设备能力

| 网页怎么用 | 容器做了什么 |
|---|---|
| `window.AppBridge.getDeviceId()` | 返回设备唯一标识（详见 §5） |
| `navigator.mediaDevices.getUserMedia()` | 相机权限申请 + 放行，扫码用 |
| `<input type="file" capture>` | 拉起系统相机 / 相册 / 文件选择，拍照上传用 |
| `localStorage` / Cookie | 已开启并持久化，登录态与设备号靠它 |

### 2.3 异常处理

| 场景 | 行为 |
|---|---|
| 无网络 | 加载前拦截，弹原生对话框（重试 / 退出） |
| 加载失败 | 显示内置错误页，**只有一个错误码**，无地址无原因（见 §6） |
| 证书有问题 | **拒绝连接**，不放行。绝不降级成不安全连接 |
| 站外链接 | 转交系统浏览器，不留在容器内 |

## 三、网络行为（网络工程师重点看这节）

### 3.1 它会连哪些地址

**只有一个**：`https://lms.sushisom.net`（解析到 `192.168.2.32`）。

| 特性 | 说明 |
|---|---|
| 协议 | **仅 HTTPS**。明文 HTTP 已在 `network_security_config` 中全局禁止 |
| 端口 | 443 |
| 出网需求 | **无**。不连任何公网服务，无统计、无推送、无崩溃上报、无自动更新 |
| 其它域名 | 白名单外的链接一律交给系统浏览器，容器自身不访问 |

> 防火墙上只需放行 平板网段 → `192.168.2.32:443`。

### 3.2 为什么必须是 HTTPS（不是可选项）

Chromium 只在**安全上下文**（https / localhost）下提供
`navigator.mediaDevices`。`http://` 页面里它**根本不存在**，
扫码功能在技术上无法实现 —— 这与权限无关，是内核规则，客户端绕不过去。

同样只在 HTTPS 下可用的还有：`crypto.subtle`、Service Worker、
`navigator.clipboard`、地理定位。

### 3.3 证书信任链

内网拿不到公网证书，采用**自建 CA + APK 内置信任锚点**：

```
内部根 CA (CN=Intranet Root CA, O=Intranet, 有效期至 2036)
   └── 签发 → 服务器证书 (SAN: DNS:lms.sushisom.net, IP:192.168.2.32)
                  ↑ 挂在宝塔面板的站点 SSL 上
   └── ca.crt 打包进 APK 的 res/raw/intranet_ca.crt
                  ↑ 在 network_security_config.xml 里声明为该域名的 trust-anchor
```

**这意味着**：

- 该域名的证书**只被这个 APK 信任**，平板的浏览器打开仍会报证书警告 —— 这是正常的，不是故障
- 证书出问题时容器**直接拒绝连接**（错误码 -1001 ~ -1005），
  不会像浏览器那样给「继续访问」的选项。这是刻意的：无条件放行等于把 TLS 关掉
- **服务器证书续期时，只要 CA 不变，APK 不用重新分发**；
  CA 换了则必须重新打包并升级所有平板

### 3.4 DNS 与内置 hosts ⭐

容器**不完全依赖设备 DNS**。这是为解决曾经的现场故障而加的（详见
[`设计与问题记录.md` 问题二](设计与问题记录.md)）。

工作方式：

```
WebView ──► 应用内的本地 CONNECT 代理 (127.0.0.1，随机端口，仅监听回环)
                │
                ├─ 命中内置映射 lms.sushisom.net → 192.168.2.32，直接连（3 秒超时）
                └─ 连不上则退回系统 DNS 解析
```

| 网络工程师需要知道的 | 说明 |
|---|---|
| **不占用固定端口** | 代理绑定的是随机端口，且只监听 `127.0.0.1`，**对局域网不可见**，无需在防火墙开任何入站 |
| **不影响 SNI 与 Host 头** | 隧道里跑的仍是发往 `lms.sushisom.net` 的原始请求，nginx 虚拟主机、Cookie 作用域、重定向全部照常 |
| **不解密流量** | 代理只做字节转发，TLS 是端到端的，代理既不参与也无法解密 |
| **服务器换 IP 时** | 映射会失效，但 3 秒后自动退回 DNS 解析。**只要 DNS 正确，不改 APK 也能继续工作** |
| 想关掉 | 编译时加 `-PhostsOverride=` 即可 |

> **给网络侧的建议**：内置 hosts 是兜底，不是替代。DNS 该配对还是要配对 ——
> 平板上除了这个 App，浏览器和其它工具仍然依赖系统 DNS。

### 3.5 曾经踩过的网络坑（避免重复）

| 现象 | 根因 | 处理 |
|---|---|---|
| App 报「无法解析服务器地址」，但浏览器能打开 | 平板 DNS 列表里排第一的是路由器通过 IPv6 RA 下发的 `fe80::` 地址，那台没有此记录，返回 **NXDOMAIN**。这是**权威否定答复**，解析器据此直接放弃，不会再问后面持有记录的服务器 | 路由器关闭 IPv6 通告；DHCP 的 DNS 只下发持有记录的那台 |
| 间歇性解析失败 | DHCP 同时下发了主备两台 DNS，备用那台会返回 NXDOMAIN | **辅 DNS 留空**，只留持有记录的主 DNS |

## 四、组件构成

```
MainActivity.kt              容器主体：编排各组件、权限、生命周期
├─ bridge/AppBridge.kt       JS 桥接，注入 window.AppBridge，只暴露 getDeviceId()
├─ device/DeviceIdProvider   设备标识：ANDROID_ID + 本地缓存兜底
├─ network/
│   ├─ NetworkChecker        加载前的网络可用性前置校验
│   ├─ HostsProxyServer      内置 hosts 用的本地 CONNECT 代理（§3.4）
│   └─ ConnectivityDiagnostics  失败后的自助诊断（解析 / 连通性探测）
├─ web/
│   ├─ AppWebViewClient      导航白名单、错误拦截、证书策略
│   ├─ AppWebChromeClient    相机权限请求、文件选择入口、加载进度
│   └─ FileChooserDelegate   拍照 / 相册 / 文件选择的完整实现
└─ assets/error.html         内置错误页（自包含，断网可渲染）
```

**权限清单**（Manifest 里只有这三个）：

| 权限 | 用途 | 不给会怎样 |
|---|---|---|
| `INTERNET` | 访问站点 | 完全无法联网 |
| `ACCESS_NETWORK_STATE` | 加载前判断有没有网 | 无法做网络前置校验 |
| `CAMERA` | 扫码与拍照 | 扫码不可用 |

**没有**：定位、通讯录、短信、存储、电话、麦克风、后台运行、开机自启。

## 五、数据存储（清了会怎样）

容器**自身**几乎不存数据，绝大部分状态在 WebView 里由网页管理。

| 数据 | 存在哪 | 谁在用 | 清掉的后果 |
|---|---|---|---|
| 登录态 Cookie | WebView Cookie 库 | 服务端会话 | 需要重新登录 |
| `vip_device`（前端设备号） | WebView localStorage | 前端审计日志 | **等于换了一台新平板**，历史审计对不上人 |
| 界面语言 | WebView localStorage | 前端 | 恢复默认语言 |
| 原生设备 ID 缓存 | 应用 SharedPreferences | `AppBridge.getDeviceId()` | 卸载重装才会清，正常使用不受影响 |

### ⚠️ 三件绝对不要做的事

| 不要 | 为什么 |
|---|---|
| 不要在代码里清 Cookie 或 WebStorage | `removeAllCookies()` / `WebStorage.deleteAllData()` 会把登录态和设备号一起清掉 |
| 不要开无痕模式 / 启动时清缓存 | 同上。**缓存可以清，Cookie 与 DOM Storage 不能清** |
| 不要加 `FLAG_KEEP_SCREEN_ON` 阻止息屏 | 门店要求息屏省电。会话要靠 Cookie 落盘扛住息屏，不是靠不息屏回避。曾经加过，已移除 |

### 登录态是怎么保住的

WebView 的 Cookie **默认只在内存里**，进程被回收就没了 ——
现场表现就是「熄屏一会儿再打开要求重新登录」。

容器在 `onPause` 和 `onStop` 各做一次 `CookieManager.flush()` 把 Cookie 落盘。

> ⚠️ **但 flush 只能持久化带 `Expires` / `Max-Age` 的 Cookie。**
> 真正的「会话 Cookie」（不带这两个属性）按定义就是不落盘的，进程一死必然丢失。
> **如果登录态需要扛住进程回收，服务端必须给登录 Cookie 设置 `Max-Age`。**
> 前端目前另有 localStorage 兜底，所以这不是阻塞项，但值得确认一次。

## 六、错误页与故障定位

**平板上只显示一个错误码**，不显示网址、也不显示失败原因 ——
容器的意义之一就是让使用者感知不到背后是个网站。

现场人员把编号报给运维，运维查
[`执行说明.md` 第八节的对照表](执行说明.md)。常用的：

| 错误码 | 含义 |
|---|---|
| `-2` | 域名解析失败 |
| `-6` / `-8` | 连不上服务器 / 超时 |
| `-1001` | APK 内置 CA 与服务器证书签发者不一致 |
| `-1002` | 证书 SAN 里没有当前域名 |
| `-1003` / `-1004` | 证书过期 / 尚未生效（后者先查平板日期） |
| 三位数 | 服务端返回的 HTTP 状态码 |

**完整信息只写进 logcat**：

```
adb logcat -s MainActivity AppWebViewClient Diagnostics HostsProxy
```

`HostsProxy` 会打印实际走的路径，用于确认内置 hosts 是否生效：

```
隧道建立(内置映射) lms.sushisom.net:443 -> 192.168.2.32:443
隧道建立(系统解析) lms.sushisom.net:443
```

## 七、需要网络 / 服务端侧配合的事项

| # | 事项 | 归属 | 说明 |
|---|---|---|---|
| 1 | 站点必须跑 HTTPS | 运维 | 否则扫码功能无法实现（§3.2） |
| 2 | 证书 SAN 必须含 `lms.sushisom.net` | 运维 | Chromium 只认 SAN，不读 CN |
| 3 | DNS 只下发持有记录的服务器 | 网络 | 辅 DNS 留空，避免 NXDOMAIN 抢答（§3.5） |
| 4 | 路由器不要下发 IPv6 DNS | 网络 | 同上 |
| 5 | 防火墙放行 平板网段 → `192.168.2.32:443` | 网络 | 仅此一条，无出公网需求 |
| 6 | 登录 Cookie 建议带 `Max-Age` | 后端 | 否则进程回收后必然丢失（§5） |
| 7 | CORS 只能服务端解决 | 后端 | **原生 WebView 没有任何开关能关闭 CORS** |
| 8 | UA 白名单要放行 `SushiVIP/1.0.0` | 后端 | 若站点有浏览器检测，别把容器拦在提示页 |
| 9 | 新增下载 / `window.open` 功能前先通知 | 前端 | 容器未实现这两项，加了会**静默失败**（点击毫无反应） |

## 八、以后要调整时改哪里

**编译期写死的配置**（改了都要重新打包并升级所有平板）：

| 要改什么 | 落点 |
|---|---|
| 目标地址 | `app/build.gradle.kts` 的 `baseUrl`，或编译时 `-PbaseUrl=` |
| 内置 hosts 映射 | 同文件的 `hostsOverride`，或 `-PhostsOverride=` |
| 域名白名单 | 同文件的 `HOST_WHITELIST` |
| 内网根 CA | `app/src/main/res/raw/intranet_ca.crt` |
| 横屏方向反了 | `AndroidManifest.xml`：`landscape` ↔ `reverseLandscape`（**代码不用动**） |
| 加载页底色 | `res/values/colors.xml` 的 `app_background` |
| 应用图标 | `python3 tools/gen_launcher_icons.py doc/logo.png` |

**不需要改 APK 就能调整的**：页面内容、样式、业务逻辑、接口、
服务器证书续期（同一个 CA）、DNS 配置。

**签名与升级**：

- 所有升级包必须用**同一个 keystore** 签名，否则平板上装不上（提示"应用未安装"）
- debug 与 release 签名不同，**不能互相覆盖**，切换前要先卸载
- `ANDROID_ID` 按签名派生，**debug 包与 release 包取到的设备 ID 不同**，
  正式建档必须用 release 包采集

**未实现、需要时可加**（各约 5 行～150 行）：

| 能力 | 现状 | 说明 |
|---|---|---|
| 文件下载 | 未实现 | 网页里的下载链接点击**无反应**。Web 侧已确认当前 0 处 |
| `window.open()` | 未实现 | 静默返回 null。Web 侧已确认当前 0 处 |
| 原生扫码 | 未实现 | 若网页版扫码在低端平板上识别慢，可改用 CameraX + ZXing 原生实现 |
| PDF 预览 | 不支持 | Android WebView 无法渲染 PDF，需前端集成 pdf.js |
